Integration guide

How to use this SDK in your own Pico project, assuming your project also builds with buildcpp rather than CMake or Bazel.

Current limitation

This SDK builds to a plain static library — there's no linker script, no boot_stage2, and no UF2 conversion step yet (see Scope & exclusions — boot_stage2 and the linker-script machinery are explicitly out of scope so far). You can compile and link your application against the SDK and get a real linked ELF with resolved symbols, which is a genuine correctness check, but turning that into something you can flash onto a physical board isn't wired up yet.

1. Add it as a submodule

git submodule add git@github.com:RubenMovsesyan/pico-sdk.git external/pico-sdk
git submodule add git@github.com:RubenMovsesyan/buildcpp.git external/buildcpp

(Adjust paths to match your project's layout — this SDK's own fork lives at tools/external/pico-sdk relative to tools/buildcpp, for reference.)

2. Build the SDK

cd external/pico-sdk
clang++ -std=c++23 build.cpp -o build   # first time only — self-rebuilds after
./build                                  # rp2040, static (what you want for firmware)

This produces external/pico-sdk/.build/rp2040/lib/libpico_sdk_rp2040.a plus the generated headers under external/pico-sdk/.build/rp2040/generated/pico_base/.

3. Wire it into your own build.cpp

Your project needs the same cross-compile flags as the SDK itself (they have to match — different --target/--sysroot/-march between your objects and the library you're linking against will not work), plus -I for every SDK component header directory your code actually #includes, plus a link against the built archive: 

#include "../buildcpp/build.hpp"

int main(int argc, char** argv) {
    initLog(4096);

    Build build(".build", "clang++", argc, argv);

    BuildGroup& app = build.addGroup();
    app.setCompiler("clang");   // same reasoning as the SDK itself: `restrict` etc.
                                  // break under clang++'s forced C++ mode

    app.addCompileFlag("--target=armv6m-none-eabi");
    app.addCompileFlag("-mfloat-abi=soft");
    app.addCompileFlag("-march=armv6m");
    app.addCompileFlag("--sysroot=/path/to/arm-gnu-toolchain/arm-none-eabi");

    // Same defines the SDK itself was built with — see platforms/rp2040.html.
    app.addCompileFlag("-DPICO_BOARD=\\\"pico\\\"");
    app.addCompileFlag("-DPICO_RP2040=1");
    app.addCompileFlag("-DPICO_32BIT=1");
    app.addCompileFlag("-DPICO_ON_DEVICE=1");
    app.addCompileFlag("-DPICO_NO_HARDWARE=0");
    app.addCompileFlag("-DPICO_BUILD=1");

    // Only the component include dirs your code actually uses — not the whole tree.
    app.addInclude(Include<Direct>("external/pico-sdk/src/rp2_common/pico_stdlib/include"));
    app.addInclude(Include<Direct>("external/pico-sdk/src/rp2_common/hardware_gpio/include"));
    app.addInclude(Include<Direct>("external/pico-sdk/src/rp2_common/hardware_uart/include"));
    app.addInclude(Include<Direct>("external/pico-sdk/src/common/pico_base_headers/include"));
    app.addInclude(Include<Direct>("external/pico-sdk/src/boards/include"));
    app.addInclude(Include<Direct>("external/pico-sdk/.build/rp2040/generated/pico_base"));
    // ...and so on for every other component header dir you touch. There's no single
    // umbrella include dir — each component publishes its own, same as the SDK's own
    // build.cpp discovers them.

    app.addLink(Link<Path>("pico_sdk_rp2040", "external/pico-sdk/.build/rp2040/lib"));

    Task& main_obj = app.addTask(Object("src/main.c"));
    app.addTask(Binary("firmware"), {main_obj});

    build.build();
    return 0;
}

Working out which include dirs you need

There's no consolidated umbrella header. If you're not sure which component a given #include lives under, grep the SDK for it: 

grep -rl "gpio_put" external/pico-sdk/src/rp2_common/*/include

or just look at compile_commands.json in external/pico-sdk/ after building it — every -I flag the SDK's own build used is right there for any file you're pulling functions from.

Testing your app against host too

If your app's logic doesn't depend on real peripheral behavior, you can build and run it natively the same way: point your include dirs at external/pico-sdk/src/host/*/include instead of rp2_common/rp2040, drop every cross-compile flag (no --target/--sysroot/-march), match the host defines from Host, and link against external/pico-sdk/.build/host/lib/libpico_sdk_host.a instead. See Host for what is and isn't real in that build.
