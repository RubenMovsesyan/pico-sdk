pico-sdk

A fork of Raspberry Pi's pico-sdk with CMake and Bazel replaced by buildcpp. This page explains how the fork is organized and how the build actually works; each topic has its own page in the sidebar.

Why this exists

Upstream pico-sdk ships ~150 CMakeLists.txt files plus a parallel Bazel build. Neither is used here. build.cpp — a plain C++ program using buildcpp — walks the source tree directly and compiles the SDK into a single static (or shared) library per platform. All the CMake/Bazel plumbing has been removed; the peripheral/runtime source code itself is untouched, straight from upstream.

The two platforms

rp2040
Cross-compiled for real hardware (src/rp2_common + src/rp2040 + src/common). Every hardware register access is real. This is what you flash to a board. See RP2040.
host
Compiled natively for the machine you're building on (src/host + src/common). Every hardware register access is a stub — gpio_get always returns 0 — but timing (sleep_ms, busy_wait_us) is real, backed by the OS clock. Good for testing logic that doesn't depend on real peripheral state; useless for anything that does. See Host.

These two are mutually exclusive within a single build: src/host and src/rp2_common define the same function names (gpio_set_function, etc.) with different bodies, so linking both into one library would collide. Pick one via --platform; each gets its own build output directory (.build/rp2040/, .build/host/) so switching between them never reuses a stale, wrong-architecture object file.

Build system

No CMake, no Bazel. build.cpp walks src/ at build time, collecting every component's include/ directory and every .c/.S file, minus a documented exclusion list (submodule dependencies that aren't vendored here, RP2350/RISC-V-only peripherals, and the "pico"-flavored default for components with multiple selectable implementations). See build.cpp for how it works and Scope & exclusions for exactly what's in and why. 

./build                    # rp2040, static (default)
./build --platform host    # host, native, static
./build --link shared      # rp2040, shared (see caveats on that page)

Conventions worth knowing

ConventionWhy
Two generated headers (pico/version.h, pico/config_autogen.h) are written by build.cpp into .build/<platform>/generated/pico_base/ before compiling.Upstream CMake generates these at configure time; they don't exist as checked-in files.
Components with multiple selectable implementations (pico_double, pico_float, pico_divider, ...) get exactly one source set baked in — the "pico" (hardware-optimized) default.Upstream defers the choice to a generator expression resolved per final executable; a single library needs one concrete answer.
Every excluded directory/file is named explicitly in build.cpp with a one-line reason in a comment.So "why isn't X in the library" always has a documented answer — see Scope & exclusions.
