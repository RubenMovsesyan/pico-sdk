Integration guide

Platform: host

Native build for the machine you're building on. Same SDK API, but hardware-touching calls compile to no-ops instead of real register access. Write and test code against this, then switch to --platform rp2040 once ready for real hardware.

Role

./build --platform host compiles src/host + src/common natively into .build/host/lib/libpico_sdk_host.a. Unlike rp2040, this produces a genuinely runnable executable when linked into an application — no bare-metal linker script needed, it's just a normal native library.

Compiler configuration

clang
  -DPICO_NO_HARDWARE=1
  -DPICO_ON_DEVICE=0
  -DPICO_BUILD=1
  -DPICO_HARDWARE_TIMER_RESOLUTION_US=1000
  -DPICO_TIME_DEFAULT_ALARM_POOL_DISABLED=1
  -DPICO_BOARD="pico"

No --target, no --sysroot, no -march — this is a native compile, not a cross-compile. No PICO_RP2040 or PICO_32BIT either; those gate rp2040-specific code paths that don't exist under src/host at all.

What's real vs. stubbed

ComponentBehavior on host
hardware_gpioPure no-op. gpio_get is a hardcoded return 0;. gpio_put does nothing observable.
hardware_timerReal. sleep_ms/busy_wait_us call the OS's actual usleep()/gettimeofday() — timing-dependent logic behaves close to real wall-clock time.
pico_multicoreHeaders-only stub, no .c at all. multicore_launch_core1() etc. aren't implemented.
Everything else (hardware_pio, hardware_adc, hardware_pwm, hardware_spi, hardware_i2c, ...)Doesn't exist under src/host at all — not stubbed, just absent. Code calling into these won't compile against the host library.

Worth knowing

  • This proves your logic compiles and runs, not that it works on hardware. Anything depending on a hardware call's return value reflecting real electrical state is meaningless here — there's no way to fake an input. Good for: state machines, protocol parsing, algorithms, anything gated by elapsed time. Useless for: anything that needs to observe a peripheral's actual behavior.
  • src/host/boot_stage2.c (a stray int main() {} sitting directly under src/host, not part of any component) is explicitly excluded — it isn't referenced by any of upstream's own CMakeLists.txt either, dead code left over in the original repo.
  • Verified end-to-end: a trivial program calling gpio_init/ gpio_put/gpio_get/sleep_ms compiles, links, and runs against this library, with gpio_get confirmed returning 0 as expected.
