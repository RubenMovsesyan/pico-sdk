Integration guide

Platform: rp2040

Cross-compiled for real RP2040 hardware. Every peripheral register access is real. This is the target you flash to a board — once a linker script and UF2 step exist (not yet, see Integration guide).

Role

The default (and only, until --platform host is passed) target of ./build. Compiles src/rp2_common + src/rp2040 + src/common into .build/rp2040/lib/libpico_sdk_rp2040.a (or .dylib/.so with --link shared — see the caveat below).

Compiler configuration

clang
  --target=armv6m-none-eabi
  -mfloat-abi=soft
  -march=armv6m
  --sysroot=/Applications/ArmGNUToolchain/15.2.rel1/arm-none-eabi/arm-none-eabi

  -DPICO_NO_HARDWARE=0
  -DPICO_ON_DEVICE=1
  -DPICO_BUILD=1
  -DPICO_RP2040=1
  -DPICO_32BIT=1
  -DPICO_BOARD="pico"
  -DPICO_THREAD_LOCAL_MODE_PER_THREAD=1

Plain clang, not clang++ — pico-sdk's C sources use restrict and other C-only idioms that break under clang++'s forced C++ mode. This matches upstream's own toolchain file exactly (CMAKE_C_COMPILER=clang, CMAKE_CXX_COMPILER=clang++).

Worth knowing

  • The ARM sysroot isn't part of any toolchain Xcode ships. Xcode's bundled clang has no bare-metal ARM sysroot at all. The path above points at a separately-installed ARM GNU Toolchain (newlib-based). If you're setting this up on a fresh machine, install that toolchain first — building will fail on the first <string.h> include otherwise.
  • --link shared doesn't currently produce a working library. Two independent problems: buildcpp's shared-link flag is chosen by host OS (-dynamiclib on macOS), which is Mach-O-specific and wrong for an ELF bare-metal target; and even correcting that, there's no armv6m compiler-rt archive available in this toolchain to link against. More fundamentally, Cortex-M0+ has no dynamic loader, so a traditionally-linked "shared library" has no real runtime meaning on this target anyway — static is what an embedded firmware library actually wants. --link static (the default) is fully verified and works.
  • 88 objects compile cleanly across every in-scope component — see Scope & exclusions for exactly what's included and what's deliberately left out (RP2350-only peripherals, RISC-V-only code, submodule-dependent components).
